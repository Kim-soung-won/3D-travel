# 공유 계획

[← 계획 (ROADMAP)](ROADMAP.md) · 작성 2026-10-21 · 상태: **1~5단계 구현 완료, 배포는 계정 연결 대기** ([09](../history/details/2026-10-21-09-sharing.md))

짠 여행 일정을 다른 사람에게 보여 주는 방법을 정리한 계획입니다. 결정은 사용자가 합니다.

## 계획 당시 상태
- **저장:** 일정이 메모리에만 있어서 새로고침하면 사라집니다.
- **배포:** 앱이 어디에도 올라가 있지 않습니다. 개발 서버(localhost)에서만 열리므로, 링크를 줘도 받는 사람이 열 수 없습니다.
- **저장소:** GitHub 저장소는 비공개입니다.
- **원칙:** 키가 필요한 서비스는 쓰지 않는다는 방향입니다([04](../history/details/2026-10-21-04-ai-prebuilt-data.md)). 서버를 두는 방식은 이 원칙과 부딪힙니다.

## 무엇을 공유하나
일정 한 벌을 공유합니다.
- 도시 목록: 이름, 보조 설명, 좌표, 다음 구간 수단, 숙박 수
- 도시별 세부 경유지: 이름, 보조 설명, 좌표, 수단

경로선(도로 좌표)은 담지 않습니다. 받는 쪽에서 다시 계산하면 되고, 담으면 링크가 수십 배 길어집니다.

## 선택지
| 방식 | 서버·키 | 장점 | 단점 |
| --- | --- | --- | --- |
| **A. 공유 링크 (일정을 URL에 담기)** | 필요 없음 | 정적 호스팅만으로 됨. 링크를 받은 사람이 바로 봄 | 링크가 김. 공유한 순간의 사본이라 이후 수정은 반영 안 됨 |
| **B. 서버 저장 + 짧은 링크** | 필요 (DB, 키) | 짧은 링크, 수정 반영, 나중에 공동 편집 가능 | 키·서버 관리, 개인 정보 보관 책임. 지금 원칙과 충돌 |
| **C. 파일 내보내기·가져오기** (`.json`) | 필요 없음 | 백업 겸용, 오프라인 전달 | 받는 쪽도 앱이 있어야 열 수 있음 |
| **D. 이미지 카드** (지구본 + 일정표 PNG) | 필요 없음 | 메신저·SNS에 바로 올림, 앱이 없어도 봄 | 보기 전용. 받은 사람이 편집할 수 없음 |

### A의 세부 설계 (권장안의 중심)
- **담는 위치:** URL의 `#` 뒤(fragment)입니다. 예: `https://<주소>/#trip=<압축 문자열>`. 이 부분은 브라우저가 서버로 보내지 않아서, 호스팅 서버 로그에 일정이 남지 않습니다.
- **인코딩:**
  1. 필요한 필드만 짧은 키로 담고, 좌표는 소수 5자리(약 1m)까지만 씁니다.
  2. 브라우저 내장 `CompressionStream('deflate-raw')`로 압축합니다. 새 라이브러리는 필요 없습니다.
  3. base64url로 바꿉니다.
- **실측 길이:**
  - 예시 일정(6개 도시, 세부 경유지 4곳): JSON 970바이트 → 압축 422바이트 → **링크 문자열 563자**
  - 도시 15곳 × 세부 8곳(반복이 많은 가상 데이터): 1,200자. 실제 일정은 이름이 제각각이라 압축이 덜 되므로 수천 자까지 늘 수 있습니다. 추정이고 측정하지 않았습니다.
- **형식 버전:** 맨 앞에 `v: 1`을 둡니다. 나중에 형식을 바꿔도 옛 링크를 읽을 수 있게 하기 위해서입니다.
- **받는 쪽 흐름:**
  - 링크로 열면 내 일정을 덮어쓰지 않고 **"공유받은 일정" 미리보기**로 보입니다.
  - [내 일정으로 가져오기]를 누르면 그때 바꾸고, 원래 일정은 되돌리기로 남깁니다.
- **잘못된 링크:** 링크가 잘렸거나 형식이 맞지 않으면 "링크를 읽지 못했습니다"를 화면 글로 보이고, 내 일정은 그대로 둡니다.
- **링크 미리보기:** 메신저의 링크 미리보기(OG 이미지)는 정적 호스팅이라 일정마다 다르게 만들 수 없습니다. 모든 링크에 같은 대표 이미지가 붙습니다.

### 공유의 전제: 자동 저장
- 공유하기 전에 새로고침해도 일정이 남아야 합니다. 브라우저 저장소(localStorage)에 일정을 자동 저장합니다.
- 키·서버가 필요 없고, 같은 형식(`v: 1`)을 씁니다.

### 공유의 전제: 배포
링크를 받은 사람이 열려면 앱이 인터넷에 올라가 있어야 합니다.

| 호스팅 | 비공개 저장소에서 | 비고 |
| --- | --- | --- |
| GitHub Pages | 무료 계정은 **공개 저장소만** 가능. 비공개는 유료 플랜 필요 | 저장소를 공개로 바꾸면 무료 |
| Cloudflare Pages / Vercel / Netlify | 무료 플랜에서 비공개 저장소 연결 가능 | 각 서비스 계정 연결(OAuth)이 필요하고, 그 과정은 사용자가 직접 함 |

- 배포하면 지도·경로·주소 조회의 공개 서버(OpenFreeMap, OSRM, Nominatim)에 요청하는 사람이 늘어납니다.
  - 개인 공유 수준은 괜찮다고 봅니다. 많은 사람에게 퍼지면 각 서버의 이용 정책을 다시 봐야 합니다([02](../history/details/2026-10-21-02-city-and-ground-modes.md)).
- 배포 주소가 생기면 README의 실행 방법 위에 "바로 써 보기" 링크를 둡니다.

## 권장안: 단계별로
| 단계 | 내용 | 서버·키 | 크기 |
| --- | --- | --- | --- |
| 1 | 자동 저장 (localStorage) | 없음 | 작음 |
| 2 | 공유 링크 만들기·열기 (A), 받은 일정 미리보기와 가져오기 | 없음 | 중간 |
| 3 | 배포 (호스팅 선택 후) | 호스팅 계정 | 작음 |
| 4 | 이미지 카드 (D), 휴대폰에서는 시스템 공유 시트(Web Share API) | 없음 | 중간 |
| 5 | 파일 내보내기·가져오기 (C) | 없음 | 작음 |
| 보류 | 서버 저장 + 짧은 링크·공동 편집 (B) | 필요 | 큼 |

- 1~2단계만으로도 같은 컴퓨터에서 링크를 열어 확인할 수 있습니다. 다른 사람에게 보내려면 3단계가 필요합니다.
- B는 "키가 필요한 서비스는 쓰지 않는다"는 지금 원칙을 바꿔야 하므로 보류에 둡니다.

- 브라우저 시나리오

  2. 새 탭에서 연다.
  3. 미리보기를 확인한다.
  4. 가져온다.
  5. 되돌린다.
  6. 같은 과정을 390px 폭에서도 확인한다.
- 링크 길이: 예시 일정 기준 600자 이하를 유지하는지 테스트로 고정합니다.

## 남은 결정
- **이미지 카드 장식:** 지금은 지구본 + 일정표만 있습니다. 도시 사진 같은 장식을 더할지 정해야 합니다.
- **링크 미리보기 이미지:** 메신저에 링크를 붙일 때 보이는 대표 이미지(og:image)는 배포 주소가 정해진 뒤 절대 주소로 넣습니다.
